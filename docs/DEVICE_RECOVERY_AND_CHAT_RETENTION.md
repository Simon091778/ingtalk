# 기기 복구 및 채팅 보관 정책

## 사용자에게 제공되는 동작

- 포인트·프로필·대화는 인증 수단이 연결된 내부 앱 계정에 귀속된다. 연결된 Google·카카오 인증은 다른 기기에서도 같은 계정을 복구하며, 전화번호 복구에는 등록 기기 확인이 필요하다.
- 일반 로그인은 별도 계정을 자동 병합하지 않는다. `begin_account_link`/`begin_account_link_v2`와 `finish_account_link`는 현재 계정·추가 인증 수단·등록 기기를 검증한 뒤 정책이 허용하는 계정을 연결하거나 통합한다. 고객지원의 임의 수동 병합 기능은 제공하지 않는다.
- 통합 시 포인트는 합산하지 않고 높은 잔액을 유지한다. 유지되는 계정의 콘텐츠를 보존하고 종료되는 계정의 콘텐츠는 이전하지 않고 삭제한다. 인증 수단과 결제 감사 기록은 서버 정책에 따라 처리한다 (`202609010006_discard_losing_account_assets_on_verified_merge.sql`).
- 앱에서는 전송 후 30일이 지나지 않은 메시지만 조회한다.
- 30일이 지난 메시지는 일반 사용자용 RLS와 채팅 목록 RPC 모두에서 제외한다.

## 서버 보관본

- 모든 메시지는 INSERT 트리거를 통해 `message_backups`에 별도로 보관한다.
- `anon`, `authenticated` 역할에는 조회·수정·삭제 권한이 없다.
- 영구 삭제는 `owner` 운영자만 `admin_delete_message_backups(bigint[], text)` RPC로 실행한다.
- 삭제 사유와 삭제 건수는 `moderation_actions` 감사 기록에 남긴다.

## 배포

```powershell
npx supabase db push
```

마이그레이션 적용 후 새 개발 빌드를 설치하고 다음 순서로 확인한다.

1. 포인트 사용 후 잔액을 기록한다.
2. 앱을 삭제하고 같은 기기에 다시 설치한다.
3. 기존 프로필과 포인트 잔액이 복구되는지 확인한다.
4. 30일보다 오래된 테스트 메시지가 앱에서 보이지 않는지 확인한다.
5. Supabase SQL Editor의 서비스 역할로 `message_backups`에 해당 메시지가 남아 있는지 확인한다.

## 운영 주의사항

- 이 기능은 배포 후 한 번이라도 앱을 실행해 기기 지갑에 연결된 계정부터 복구할 수 있다.
- 현재 기기 지문은 개발 단계의 최선 노력 방식이다. 유료 포인트를 도입하기 전 Android Play Integrity와 iOS DeviceCheck 검증을 Edge Function에 추가해야 한다.
- 서버 보관본의 목적, 보관기간, 관리자 삭제 기준을 이용약관과 개인정보 처리방침에 명시해야 한다.
